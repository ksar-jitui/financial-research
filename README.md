# 年报语调操纵审计 Agent

输入任意一只 A 股的代码，它会去巨潮资讯下载那一年的年报、把「管理层讨论与分析」（MD&A）整段读出来，
然后用大模型评估**这些表述相对当年财务基本面被美化了多少**，输出一条带证据链的风险预警——
每一句结论都能点回年报原文的对应段落。

**在线体验（公开、免登录，全部数字来自真实数据）：** https://mda-tone-audit-mwsjkulrp4b.qoder.zone

这不是一个「财务好不好」的打分器。它只回答一个问题：**管理层说得漂亮的地方，有没有数据支撑。**
一家公司可以财务很健康、同时表述很浮夸（贵州茅台 2024 就是这种），也可以财务正在恶化、
同时语气依然平稳——后一种才是年报里最难被外部读者发现的东西。

```bash
git clone https://github.com/ksar-jitui/financial-research.git
cd financial-research
```

### 本地版（Streamlit）

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .streamlit/secrets.toml.example .streamlit/secrets.toml   # 填入你自己的 DashScope key

```

数据侧不需要任何 key：财务数据走东方财富公开接口，年报 PDF 走巨潮资讯（请求间隔 ≥2 秒）。
只有大模型调用需要 key，且只从 `st.secrets` 读取，不进前端、不进仓库。

### 线上版（Qoder Sites）

`site/` 是纯静态前端，`functions/` 是一个 edge function（`app`），前端只发同源请求
`/functions/v1/app?action=...`。密钥在 Sites 的 Secret 配置里以同名 `DASHSCOPE_API_KEY` 登记。
PDF 解析在浏览器本地完成（pdf.js），所以几 MB 的年报不必穿过函数网关。

## 二、四个 Agent

| Agent | 模型 | 干什么 |
| --- | --- | --- |
| TextSentimentAgent | qwen-plus | 分块读 MD&A，输出 0–100 的**语调虚高指数**与带段号的关键论点。同一段文本**并行跑两遍取均值**，两遍不一致的段落单独标出——方向是结论，不可复现就不能当证据。 |
| FinancialHealthAgent | 规则引擎（无模型） | 输出两个数：**水平分**（当年基本面）与**同比变化分**（同一套规则在少一年的窗口上重算后的差值）。Piotroski F-Score 在这里是**被引用的输入项**，不是判定锚。 |
| FactReviewAgent | qwen-plus | 先按「含计量数值 + 含财务指标名词」确定性抽取摘录，独立核对两次，逐项给指标类别、比较口径、原因归属与交叉一致性；两次不一致的条目标为「分歧」，不作为结论。 |
| LeaderAgent | qwen-max | 比对背离度、财务分位与事实核对结论，**强制复核红线**（模型不得推翻规则算出的档位），输出带证据链的预警。 |

两套运行时共享同一套判据：`functions/lib/agents.ts`（线上）与 `audit_agents.py`（本地）。

## 三、判据

```
背离度 = 语调虚高指数 − 财务基本面「最差一侧」的百分位
最差一侧 = min(水平分位, 同比变化分位)
红线 ≥ 65 判定异常    黄线 ≥ 50 需核查    其余 绿
```

**为什么减百分位而不是原始分**：全市场普查测出水平原始分的 p1–p99 跨 **163.7 分**（−51.7 ~ 112.0），
而语调指数只在中高段走动。两个量纲差一个数量级的数相减，差值的方差几乎全来自财务侧——
「背离度」会退化成财务分的负数镜像，语调高已经无所谓了。换成百分位后两侧同为 0–100，
缺口才真的表示「表述相对基本面的超出量」。

**为什么取最差一侧**：被掩饰的既可能是「本来就差」，也可能是「水平仍高但正在下滑」，后者是年报操纵里最常见的一种。

**切点不是拍的**。把「最差一侧」在这 27,708 个观测上的经验分布测出来是
p10 = 7.4　p25 = 18.9　p50 = 40.0　p75 = 64.6　p90 = 82.4，
于是红线缺口 65 对应的全市场基础命中率是：

| 语调虚高指数 | 75 | 80 | 85 | 88 |
| --- | --- | --- | --- | --- |
| 红线命中率 | 13.3% | 19.6% | 26.4% | 30.4% |

也就是说，即使一家公司语调高达 88，也要它的财务最差一侧落到约第 23 百分位以内才会亮红。
界面上这张表由函数实时从参照分布算出，不是写死的文案。

旧版红线是「语调 > 80 且健康分 < 50」——两个数都没有实测依据（实测水平分的第 50 百分位是 56），
而且在任何一家真实公司上都没有触发过。

### 判定用哪个池子

同一个降幅，在板块普跌与板块独跌两种语境下性质完全不同。所以分位定位按
**一级板块 → 实体/金融 → 全市场** 依次退回，并如实写出最终用的是哪一层。
行业归属来自东方财富 `RPT_F10_ORG_BASICINFO` 的官方一级板块（免 key、单公司一次请求），取不到就退回上一层，绝不猜。

**优质档自动降档**：毛利率与净利率**同时**处于行业前 5% 时，预警级别下调一档（红→黄，黄→绿）。
降档只改级别不改分数，原始档位与降档理由都保留在结论里；降档后核查重点相应从
「是否掩盖恶化」转为「是否把周期性失速表述为稳健增长」。

这条规则的代价必须一并写明：按行业定位会在**板块系统性下行**时给出更宽松的档位。
本工具选择接受这个代价，但结论应理解为「与同行相比的表述缺口」，不是「与公司历史相比的表述缺口」。

### 现金流怎么计量恶化

同比增速的分母是**基期绝对值**，而基期正是那个正在塌的数：基期 +0.03 亿、本期 −0.51 亿会报出
**−1706%**，可绝对缺口只有 0.54 亿。所以计分改按 **Δ ÷ 上年营业收入** 分档：
≤ −15% 扣 20 分、≤ −5% 扣 10 分，绝对缺口不足 0.2 亿的既不扣分也不进异常列表
（上年营收取不到时退回旧口径，不留一个无声的「不扣分」）。阈值来自 200 家真实公司的下降样本分布
（p10 −19.2%、p25 −13.1%、p50 −6.2%）；0.2 亿的下限在这批样本上只挡掉 1 家 mild 档，
而 0.5 亿会连挡 2 家真实的前 15% 缺口。分母用**上年**而非本年营收，是为了不把同一次下滑计两次。
异常条目里直接写出「缺口相当于上年营收的 X%」，判分依据在界面上就能核对。

同一处修正也覆盖了展示层：基期与本期异号时写「由正转负／由负转正」，|增速| > 100% 时把百分比降为括号里的辅助数，
柱状图对超出 ±200% 的柱子截断贴边。

## 四、参照分布：全市场普查，不是抽样

分位带由**本仓库同一套规则** `scoreRows` 对全市场 A 股年报行逐条打分算出：

- 名录 **5579 家**，全部取到可比年报，共 **27,708 个年度观测 / 22,119 个同比变化观测**，年度覆盖 2021–2025；
- 一级板块 31 组，其中 **25 组**观测数达到建带门槛 300，合计覆盖 26,602 / 27,708（96.0%）；
- 因为是普查而非抽样，这里没有抽样误差；未进入分布的只有取数失败或不足两个可比年报的公司，不假装覆盖。

复现路径（免 key，约 12 分钟）：

```bash
# 需要 Node ≥ 22（本项目用 Electron 自带 Node 跑：ELECTRON_RUN_AS_NODE=1 <electron> 文件.mts）
_dev/ref_census.mts        # 逐家取数并按同一套规则打分 → _dev/ref_rows_v2.jsonl（缓存，不入库）
_dev/ref_stats.mts         # 分位数 → functions/lib/reference_bands.ts 与 reference_bands.py（同源同值）
_dev/ref_calibrate.mts     # 命中率核对
```

普查缓存与跑批产物都在 `.gitignore` 里，仓库只保留脚本本体。

## 五、实测案例

| 案例 | 结果 |
| --- | --- |
| 长安汽车 2024 | 水平分 7（汽车带 n=1602，第 9.7 百分位）、同比变化第 4.1 百分位，实测语调 71.08 → **背离度 66.98，红线**；界面标题与档位一致 |
| 贵州茅台 2024 | 原始分 104、食品饮料带第 85 百分位 → **绿灯**。它在《中国上市公司健康指数》里是全市场第一（82.61）——「水平很高」和「表述没美化」不是同一件事，这条恰好是本工具与现有健康指数不同轴的证明 |
| 晶升股份 2025 | 营收 −72.8%、归母与现金流双双由正转负，实测语调 77.85 → **背离度 74.65，红线**；现金流缺口按新口径读作「上年营收的 12.8%」而不是 −1706% |
| 负控对照 | 18 对同行业配对样本（优质 vs 恶化），语调轴与质量轴独立（p = 0.81）——它没有把「公司好」直接读成「说得少」 |

## 六、已知边界（不粉饰）

1. **没有预测效度。** 用 2024 年的背离度去预测 2025 年业绩，Spearman ρ = −0.070，95% CI [−0.233, +0.097]；
   控制行业与规模后偏相关 ρ = −0.004（p ≈ 0.96）。所以本工具输出的是**审计风险线索**，
   不是能赚钱或能定罪的信号。任何把它当预测模型用的读法都超出了它被验证过的范围。
2. **语调侧依赖模型。** qwen-plus 的打分有波动，因此做了双跑与段号白名单；但「可复现」不等于「正确」。
3. **本地引擎是线上规则的子集**（数据层缺扣非字段，净现比与扣非背离不参与打分）。
   48 个配对观测实测本地分相对线上分中位 −6.3、范围 −17 ~ +18，其中 22.9% 的观测 |差值| ≥ 10。
   所以本地读到的百分位是**近似定位**，幅度是十位数级别。
4. **限流已实现但未启用。** 每 IP 每 24 小时 5 次完整审计的规则、去重键与界面提示都写好了，
   由 `QUOTA_ENFORCED = false` 关闭；计数存在 edge 实例进程内存里，不跨实例共享、重启即清零，
   所以它是尽力而为的节流，不是硬保证。
5. 词典法（正面词占比）按构造只数「表述立场」，不含「是否有数据支撑」这一维，
   因此只作交叉验证，**不作为语调虚高指数的证据**。
6. 结论是风险预警，不是违法事实认定，也不构成投资建议。

## 七、目录结构

```
app.py / audit_agents.py / data_processing.py / data_fetching.py   本地 Streamlit 运行时（四 Agent 与数据层）
reference_bands.py                                                  本地运行时的参照分布（与线上同源生成）
site/            线上版静态前端（含 pdf.js 与浏览器端 MD&A 解析、整页高亮快照）
functions/       线上版 edge function：lib/agents.ts 是判定内核，lib/reference_bands.ts 是分位带
_dev/            可复现工具：全市场普查、分位数生成、切点核对、效度与前瞻验证、引擎差测量
tests/           早期分层原型（app/ agents/ core/ utils/ config/ data/）的测试
```

`app/`、`agents/`、`core/`、`utils/`、`config/` 与 `data/{models,acquisition,processing}` 是项目最初的分层原型，
**当前跑的产品不依赖它们**，只有 `tests/` 在测它们。保留是为了让演进过程可查，删掉会让那批测试失效。

## 八、数据源、密钥与第三方

- 股票名录与财务数据：东方财富公开接口（免 key）。年报 PDF：巨潮资讯（请求间隔 ≥2 秒）。名录缓存来自 AKShare。
- 大模型：阿里云百炼 qwen-plus / qwen-max。密钥线上放 Sites Secret、本地放 `.streamlit/secrets.toml`，
  两者都被 `.gitignore` 排除；仓库里只有 `.streamlit/secrets.toml.example` 占位模板。
- 本仓库**不含**任何年报 PDF、快照图片与下载数据（体积与版权原因），克隆后按需现取。
- `site/assets/pdf.min.js` 与 `pdf.worker.min.js` 来自 pdf.js（Apache-2.0）。

## 九、这是怎么用 Qoder 做出来的

判定内核、全市场普查脚本、两套运行时的同步、以及线上 504 与限流的定位，都是在 Qoder 里
由 agent 直接读写代码、跑 Electron 自带的 Node、驱动浏览器实测完成的；每一个阈值改动都要求
「先测出分布、再定切点、再把依据表同步到界面」，所以方法论页面上的每个数字都能回溯到 `_dev/` 里的脚本。
